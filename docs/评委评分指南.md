# ScoreSys 立项评审评分指南

**适用对象：** Walker、Nadia、Jarvis、Gouki、Ollie、Simon 等评委

**适用版本：** 项目池 V2 + 两轮评分 V4

**系统地址：** https://scoresys.vercel.app

> 本指南只说明评委端的操作流程和评分逻辑。账号密码由管理员单独发放。

## 一、登录与开始评分

1. 打开系统地址。
2. 使用管理员发放的账号和密码登录。系统不会要求额外的 Vercel 网络验证。
3. 登录后进入评委评分页面 `/scoring`。
4. 页面默认打开当前评审会；如存在多个评审会，可在页面中选择需要评分的评审会。
5. 从左侧项目列表选择项目，右侧进入评分。
6. 项目顶部会显示：
   - 评审阶段：创意阶段或立项阶段。
   - 评审次数：第一次或第二次。
   - 资料状态：资料齐全或待补充进度。

评审会本身不区分轮次，轮次和次数以项目当前显示为准。

## 二、两轮评审流程

### 第一轮：游戏性 / 创新性

所有评委对项目进行游戏性和创新性评分。第一轮结束后，由 Walker 给出本轮最终结论：

| Walker 结论 | 项目后续状态 |
| --- | --- |
| 通过 | 进入第二轮，等待管理员安排下一场评审会 |
| 重评 | 留在第一轮，获得 1 次重评机会 |
| 驳回 | 项目立项取消 |

### 第二轮：立项综合评估

通过第一轮的项目由管理员安排到新的评审会。当前新建第二轮采用六维综合评估，所有评委再次参与评分。第二轮结束后，Walker 再次给出最终结论：

| Walker 结论 | 项目后续状态 |
| --- | --- |
| 通过 | 进入立项流程 |
| 重评 | 留在第二轮，获得 1 次重评机会 |
| 驳回 | 项目立项取消 |

每一轮最多重评 1 次。第二次评审时只能选择“通过”或“驳回”，不能再次选择“重评”。

## 三、第一轮评分方法

第一轮基础总分为 100 分。

| 维度 | 满分 | 评分方式 |
| --- | ---: | --- |
| 游戏性 | 60 | 4 个子项分别打 0-10 分，先求子项平均分，再乘以 6 |
| 创新性 | 40 | 直接选择创新性档位，系统按所有评委选择结果取中位数 |

### 1. 游戏性子项

每个子项均为 0-10 分：

- 核心玩法
- 体感适配性
- 可复玩性
- 年龄适配度

计算公式：

```text
游戏性得分 = 4 个子项平均分 × 6
```

### 2. 创新性档位

创新性不填写 0-10 数字，而是直接选择一个档位：

| 档位 | 分值 | 参考含义 |
| --- | ---: | --- |
| L1 | 10 | 平台已有，基本为完全复制 |
| L2 | 16 | 已有体感标杆 |
| L3 | 24 | 类似已有标杆 |
| L4 | 30 | 部分原创 |
| L5 | 40 | 完全原创，全自研独创 |

创新性最终得分由系统根据所有评委的有效选择取中位数，不是简单平均。

```text
第一轮基础总分 = 游戏性得分 + 创新性得分
```

## 四、第二轮评分方法

当前新建第二轮基础总分为 100 分，所有会议评委均按页面显示的全部维度参与评分。当前 V4 规则如下：

| 维度 | 满分 | 评分方式 |
| --- | ---: | --- |
| 游戏性 | 25 | 4 个子项平均分 × 2.5 |
| 创新性 | 20 | 直接选择档位，系统取中位数 |
| 项目规划 | 15 | 4 个子项平均分 × 1.5 |
| 技术&美术 | 15 | 2 个子项平均分 × 1.5 |
| 风险预估 | 15 | 4 个子项平均分 × 1.5 |
| 造价与预算 | 10 | 3 个子项平均分 × 1 |

### 1. 游戏性子项

与第一轮相同：核心玩法、体感适配性、可复玩性、年龄适配度。

### 2. 创新性档位

第二轮使用独立的创新性档位：

| 档位 | 分值 | 参考含义 |
| --- | ---: | --- |
| L1 | 8 | 平台已有，基本为完全复制 |
| L2 | 10 | 已有体感标杆 |
| L3 | 12 | 类似已有标杆 |
| L4 | 14 | 部分原创 |
| L5 | 20 | 完全原创，全自研独创 |

### 3. 项目规划子项

- 项目里程碑
- 文档完善程度
- 风险难点分析
- 外包方案合理度

### 4. 技术&美术子项

- 技术方案评审
- 美术方案评审

### 5. 风险预估子项

- 延期风险
- 方向风险
- 资源风险
- 政策版权风险

### 6. 造价与预算子项

- 预算合理性
- 成本控制
- 投入产出预期

```text
第二轮基础总分 = 六个维度换算分之和
```

## 五、评委可以填写的内容

### 所有评委都可以填写

- 当前轮次的全部评分维度和子项。
- 本轮个人项目评级：S / A / B / C。
- 本轮个人评审结论：通过 / 重评 / 驳回。
- 存在问题：建议每行填写一条。
- 改进行动：建议每行填写一条。

个人评级和个人结论属于盲评参考，系统会在管理员汇总和报告中统计数量、比例，但不会替代 Walker 的最终结论。

### 只有 Walker 可以填写

- Walker 本轮加分：额外 0-5 分，并填写加分原因。
- Walker 最终评审结论：通过 / 重评 / 驳回。
- 项目最终评级：S / A / B / C。

Walker 加分单独记录，不改变本轮基础分 100 分的满分口径。报告中会区分基础分和加分。

## 六、保存与修改规则

1. 数字评分框可以输入 `0`，也可以先清空再重新输入。
2. 数字评分通常在失焦后保存；滑块和档位选择会触发保存。
3. 文字意见可以继续修改，点击保存评审意见后提交；输入过程中系统也会尝试保存。
4. 个人评级、个人结论和 Walker 加分保存后，页面右上角会出现保存中、保存成功或保存失败提示。
5. 看到“保存成功”后再切换项目，可以避免网络较慢时产生误判。
6. 评审截止日期前，可以反复打开项目修改自己的分数和意见。
7. Walker 已经提交结论后，其他评委仍可以继续查看和修改本场评审会中的项目，直到截止时间。

## 七、盲评与汇总逻辑

- 普通评委的个人评级会统计为 S/A/B/C 数量和比例。
- 普通评委的个人结论会统计为通过/重评/驳回数量和比例。
- 管理后台展示的是所有评委当轮分数的维度平均结果。
- 普通维度：先按每个子项汇总所有评委的平均分，再按维度系数换算。
- 创新性：按所有有效档位取中位数。
- Walker 最终结论是项目状态流转和项目评审历史的依据。
- Walker 加分不计入基础分完成度和基础满分，只作为额外分展示。

## 八、评分时的建议

- 先完整阅读项目资料，再开始打分。
- 分数应以当前轮次的评估目标为准，不要用第一轮标准替代第二轮标准。
- 对评分较低的项目，尽量在“存在问题”中写清具体原因。
- 对可以执行的改进方向，尽量在“改进行动”中写清动作、目标或验收标准。
- 创新性档位请根据项目实际创新程度选择，不要把档位当成普通数字分数输入。
- 如果发现项目名称、资料状态、评审轮次或项目内容明显不正确，请先联系管理员，不要在错误项目上继续提交评分。

## 九、异常处理

| 现象 | 处理方式 |
| --- | --- |
| 页面打不开 | 刷新页面，确认网络后重新打开正式地址 |
| 登录失败 | 确认账号密码，仍失败时联系管理员检查账号状态 |
| 保存提示失败 | 不要连续快速点击，等待后重试；仍失败时截图反馈项目名和操作项 |
| 项目列表为空 | 确认管理员已将项目加入当前评审会，并确认登录账号正确 |
| 评分框出现旧值 | 刷新页面后重新读取；不要直接提交未确认的旧值 |
| 看不到最终评级 | 普通评委不显示最终评级属于正常权限设计；Walker 如看不到请联系管理员 |

## 十、联系管理员时请提供

- 评委账号
- 项目名称
- 当前评审会名称
- 第一轮/第二轮及第一次/第二次
- 具体操作（评分、档位、意见、评级或结论）
- 页面提示内容或截图
